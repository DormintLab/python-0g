## Project Overview

This is a **Python client library for the 0G.ai on-chain inference network**. The project provides OpenAI-compatible clients for accessing AI providers on the 0G blockchain network, with local request signing and on-chain service discovery.

### Architecture Highlights

- **Hybrid Python/JavaScript Implementation**: Core blockchain interactions happen in JavaScript/TypeScript (in `a0g/jsbindings/`), consumed by Python via the `javascript` package
- **OpenAI-Compatible Interface**: Drop-in replacement for OpenAI SDK with both sync and async clients
- **On-Chain Service Discovery**: Dynamically discovers AI providers via smart contracts
- **Local Wallet Signing**: Signs requests locally with EVM private keys for security

## Development Commands

### Python Development

#### Setup
```bash
# Install Poetry if not already installed
pip install poetry

# Install dependencies
poetry install

# Activate virtual environment
poetry shell
```

```bash

poetry run ruff check .

# Run type checking

poetry run isort .

poetry run python -m pytest tests/test_jsbindings.py -v
```

```bash

poetry run pyclean .

# Build the package
poetry build

# Install the built package locally
pip install dist/python_0g-*.whl
```

```bash

pnpm install
```

## Key Architecture Components

### Multi-Language Integration
- **Python Wrapper** (`a0g/base.py`): Main `A0G` class providing high-level interface
- **JavaScript Core** (`a0g/jsbindings/src/index.ts`): Core blockchain and service discovery logic
- **Bundle Bridge** (`a0g/jsbindings/dist/bundle.js`): Compiled JavaScript consumed by Python
- **Smart Contracts** (`a0g/contract/`): Contract addresses and ABI management

### Network Configuration
- **Testnet** (default): `https://evmrpc-testnet.0g.ai`
- **Mainnet**: `https://evmrpc.0g.ai`
- **Contract Addresses**: Managed in `a0g/contract/__init__.py` with network-specific configurations

### Core Functionality Flow
1. **Initialization**: Python `A0G()` class loads JavaScript bundle via PyExecJS
2. **Service Discovery**: Queries on-chain contracts to find available AI providers
3. **Client Generation**: Creates OpenAI-compatible clients with proper authentication headers
4. **Request Signing**: Local wallet signing for all provider requests

## Environment Configuration

Required environment variables:
- `A0G_PRIVATE_KEY`: EVM private key (hex string without 0x prefix)
- `A0G_RPC_URL`: Custom RPC endpoint (optional, defaults based on network)

Optional overrides:
- `A0G_INFERENCE_CA`: Override inference contract address
- `A0G_LEDGER_CA`: Override ledger contract address

## Project Structure

### Python Package (`a0g/`)
- `base.py`: Main A0G class and public interface
- `common/utils.py`: Utility functions
- `contract/`: Contract addresses and ABI management
- `types/`: Type definitions (account, headers, ledger, model, etc.)
- `d402/`: Domain-specific module
- `jsbindings/`: JavaScript/TypeScript core implementation

### JavaScript Core (`a0g/jsbindings/`)
- `src/index.ts`: Main API functions for service discovery and header generation
- `dist/bundle.js`: Compiled bundle consumed by Python (generated by `pnpm build:bundle`)
- `package.json`: Node.js dependencies and build scripts

### Testing
- `tests/test_jsbindings.py`: Basic integration test for JavaScript bridge
- No comprehensive test suite currently implemented

## Development Workflow

### Making Changes

1. **For Python changes**: Edit files in `a0g/` directory, test with `poetry run python tests/test_jsbindings.py`
2. **For JavaScript changes**:
   - Edit `a0g/jsbindings/src/index.ts`
   - Run `cd a0g/jsbindings && pnpm build:bundle` to update bundle
   - Test Python integration

### Critical Dependencies
- **Python**: web3, openai, javascript (for JS bridge), notebook
- **JavaScript**: @0glabs/0g-serving-broker, ethers, crypto-js
- **Build Tools**: esbuild (JavaScript bundling), TypeScript, Poetry (Python)

## Common Development Patterns

### Adding New Service Types
1. Add type definitions in `a0g/types/`
2. Update contract interactions in `a0g/jsbindings/src/index.ts`
3. Rebuild bundle with `pnpm build:bundle`
4. Update Python interface in `a0g/base.py`

### Network Configuration Changes
1. Update contract addresses in `a0g/contract/__init__.py`
2. Test with different `A0G_RPC_URL` values
3. Verify both testnet and mainnet functionality

### Debugging JavaScript Bridge
- JavaScript errors appear in Python console
- Use `console.log()` in TypeScript, visible in Python output
- Bundle must be rebuilt after JavaScript changes

## Important Notes

- **Bundle Dependency**: Python integration depends on the JavaScript bundle being up-to-date
- **Node.js Requirement**: JavaScript package requires Node.js to be installed and accessible
- **Wallet Security**: Private keys are handled locally, never transmitted to servers
- **Network Dependencies**: All functionality requires valid wallet funding and network connectivity
